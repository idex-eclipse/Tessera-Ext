# Плагин Tessera: Диагностика движения

[English version](README.md)

Необязательный плагин Tessera, который переносит **motan** из Klipper (`scripts/motan`:
`data_logger.py`, `motan_graph.py`, `data_export.py`) в браузер. Записывайте данные движения,
моторов, акселерометра, тензодатчика, датчика угла, вихретокового датчика и stallguard TMC,
считайте производные ряды (производная, интеграл, фильтры, отклонение от ожидаемого положения
мотора) и смотрите графики без командной строки, Python и файлов на принтере. Плагин добавляет
вкладку **Диагностика движения** на страницу *Система* через точку расширения
`@core/system#tabs`. Написан на [Lit](https://lit.dev) с [uPlot](https://github.com/leeoniya/uPlot).

## Требования

- Tessera с plugin API **1.0** или новее и `@core/system` **4.0.0** или новее.
  `tessera-ext` не ставит плагин на более старую Tessera.
- Klipper в состоянии *ready* на время записи. Для открытия сохранённого лога принтер не нужен.
- Сырой мост Moonraker `/klippysocket`. Сайт nginx Tessera проксирует его так же, как
  `/websocket` (добавляет `install.sh`; на уже установленной Tessera выполните *Update*).
  Без него записать ничего нельзя.
- То, что вы хотите записать, должно быть в `printer.cfg`: `[adxl345]`, `[lis2dw]`,
  `[mpu9250]`, `[bmi160]`, `[icm20948]` или `[lis3dh]` для акселерометров, `[angle]`,
  `[probe_eddy_current]`, `[load_cell]` / `[load_cell_probe]` и драйвер TMC
  (`tmc2130`, `tmc2209`, `tmc2240`, `tmc2260`, `tmc5160`, `tmc5262`) для stallguard. Движение
  (`trapq`) и очереди шагов моторов даёт сам Klipper.

## Как пользоваться

1. **Запись.** Вкладка спрашивает у Klipper, что можно записать, и показывает это группами.
   Как в motan, по умолчанию отмечены trapq и stepq. Отметьте нужное, задайте лимит времени и
   нажмите **Записать**, затем выполните движение, которое хотите изучить. **Остановить**
   завершает запись. Данные хранятся в памяти этой вкладки браузера; запись продолжается, если
   переключиться на другую вкладку страницы «Система».
2. **Анализ.** Первая подходящая раскладка рисуется сразу. Другую выберите в списке
   *Раскладка* (она применяется и рисуется при выборе) или соберите свою: **Добавить ряд**
   открывает форму, где выбирают вид данных и заполняют параметры из списков того, что есть в
   записи. Вычисляемые ряды (разность двух рядов, фильтр на акселерометре) открывают вложенные
   формы. *Начало*, *Длина* и *Шаг по времени* — это `--skip`, `--duration` и `--segment-time`
   из motan. После их изменения или смены рядов нажмите **Построить графики**.
3. **Просмотр.** Один график на строку, общая ось времени: выделите область, чтобы
   увеличить, **Shift + колесо** масштабирует ось времени вокруг курсора (вверх — приближает,
   вниз — отдаляет), двойной щелчок сбрасывает масштаб; все строки масштабируются вместе. Ряды с
   другими единицами уходят на вторую ось справа, как в motan. Длинные ряды прореживаются для
   рисования с сохранением минимума и максимума на каждый пиксель, поэтому выбросы видны;
   при увеличении детали возвращаются. Цвет и прозрачность задаются для каждого ряда.
4. **Сохранение.** См. ниже.

### Что можно рисовать

| Данные | Величины |
|---|---|
| Заданное движение (`trapq`) | положение, скорость, ускорение головы, суммарно или по оси |
| Положение мотора (`stepq`) | заданное положение, восстановленное из очереди шагов, со временем сглаживания |
| Фаза мотора (`step_phase`) | фаза или микрошаг (нужны секция TMC и очередь шагов мотора) |
| Акселерометр | одна ось |
| Датчик угла | положение мотора, на котором он стоит (по `rotation_distance` и `gear_ratio`) |
| Вихретоковый датчик | частота катушки, период, оценка высоты |
| Тензодатчик | усилие в граммах, «сырые» отсчёты АЦП |
| Stallguard TMC | результат stallguard, уровень тока |
| Поле статуса | любое числовое поле статуса принтера в том виде, как оно менялось во время записи |

Вычисляется из других рядов: **производная**, **интеграл** (можно с опорным рядом),
**длина вектора** из двух или трёх рядов, **сглаживание**, **фильтр** (Баттерворта нижних,
верхних частот, полосовой или режекторный, причинный или с нулевой фазой), **ожидаемое
положение мотора** по движению головы (cartesian и CoreXY), **положение головы CoreXY** по двум
моторам и **разность**.

Готовые раскладки предлагаются только для того, что есть в записи: скорость и ускорение,
отклонение моторов (набор motan по умолчанию), акселерометр (обычный и с полосовым фильтром),
тензодатчик, stallguard, датчики угла, вихретоковый датчик, фаза мотора.

## Сохранение и открытие

| Кнопка | Файл | Для чего |
|---|---|---|
| Скачать лог motan | `<имя>.tar.gz` с `dump.json.gz` и `dump.index.gz` | Запись в формате `data_logger.py`. Распакуйте и запустите `motan_graph.py dump` или `data_export.py dump` на компьютере со скриптами Klipper. Эта вкладка тоже откроет его обратно |
| Скачать PNG | `<имя>.png` | Все графики одной картинкой с осями, подписями и легендами, как вы их видите (масштаб сохраняется) |
| Скачать CSV | `<имя>.csv` | Данные построенных графиков таблицей в раскладке `data_export.py` |
| Открыть лог… | | `.tar.gz`, сохранённый здесь, или два файла `*.json.gz` и `*.index.gz`, сделанные `data_logger.py` на принтере (выберите оба сразу) |

Файлы называются `motion-diag-<принтер>-<дата>-<время>`. Ничего не загружается ни на принтер,
ни куда-либо ещё.

## Чем отличается от motan

Декодеры и анализаторы — порт кода motan, они дают те же числа: результат сверен с настоящим
`data_export.py` на реальной записи и на синтетических (см. ниже). Намеренные отличия:

- Параметр `skip` читает лог с начала, а не переходит по индексу. Результат тот же, на очень
  длинных логах медленнее.
- Два ряда `stallguard` одного драйвера здесь независимы. В motan они делят список сообщений
  и при одновременном запросе отбирают друг у друга каждый второй отсчёт.
- Нечисловое поле `status(...)` рисуется как разрыв, а не выводится текстом.
- `kin(...)` поддерживает только кинематики cartesian и CoreXY, как и motan.
- В экспортируемом логе одна запись индекса (см. выше).

## Ограничения и затраты

- Всё хранится в памяти браузера. Запись сама останавливается по лимиту времени (по умолчанию
  60 с) или примерно при 200 МБ оценки памяти. Тяжелее всего `stepq`: на больших скоростях
  данных очень много. Записывайте только нужные моторы.
- Считается не более 400 000 точек на ряд; при шаге по умолчанию 0,1 мс это 40 с. Увеличьте
  шаг или сократите окно.
- В Klipper нет «отписки»: поток идёт, пока открыт сокет моста, поэтому запись нагружает
  Klipper. Останавливайте её, когда закончили; закрытие вкладки тоже останавливает.
- Расчёт идёт на странице порциями (без Web Worker: CSP Tessera по умолчанию его не
  разрешает), страница остаётся отзывчивой, но длинное окно с мелким шагом считается секунды.

## Разработка

```bash
cd plugins/motion-diag
npm install
npm test            # модульные тесты, сверка с motan, контракт UI
npm run typecheck
npm run dev         # сборка при изменениях в <Tessera>/extensions/motion-diag/
npm run pack        # сборка и запись архива в registry/
```

Сверка с motan лежит в `src/__tests__/fixtures/`: записи в формате `data_logger.py`
(синтетические принтеры cartesian и CoreXY) и CSV, которые для них написал настоящий
`data_export.py`. Их создаёт `tools/gen_fixtures.py` (нужны копия Klipper и Python с NumPy и
SciPy); `tools/gen_dsp_fixtures.py` делает то же для фильтров SciPy. Чтобы проверить запись
своего принтера, запустите на ней `tools/gen_real_expected.py`: результат попадёт в
игнорируемую git папку `local/`, а `src/__tests__/real-log.test.ts` сравнит с ним порт
в браузере.
