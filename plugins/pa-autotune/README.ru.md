# Плагин Tessera: PA Autotune

[English version](README.md)

Необязательный плагин Tessera, который встраивает в страницу *Calibrations* веб-интерфейсы двух
Klipper-модулей автокалибровки Pressure Advance: **[autopa](https://github.com/G0BL1N/autopa)** и
**[KAPAT](https://github.com/vzagranichnyy/KAPAT)**. Оба измеряют Pressure Advance по датчику усилия
в сопле и поставляются со своим веб-интерфейсом. Плагин определяет, какой из них установлен на
принтере, и показывает его интерфейс в `<iframe>` во вкладке **PA Autotune**. Написан на
[Lit](https://lit.dev), как и плагин Pressure Advance tester.

| Поверхность | Что делает |
|---|---|
| Дополнение `@core/calibrations#tabs` (вкладка, append) | веб-интерфейс установленного провайдера в iframe; переключатель, если установлены оба; инструкция по установке, если нет ни одного |
| Оверлей (пустой) | держит api плагина доступным для гарда с запуска приложения |
| Гард `printer.gcode.script` | `AUTOPA_SWEEP`, `AUTOPA_DECAY` и `KAPAT_SWEEP` от других плагинов (консоль Tessera, макросы) отклоняются во время печати и паузы |

Вкладка в Calibrations **есть всегда**. Без провайдера она объясняет, как установить каждый из них
(клонировать, `install.sh`, секция `[autopa]` / `[kapat]`, полный перезапуск Klipper), и ссылается
на репозитории.

## Требования

- Klipper с установленными из их репозиториев `autopa` и/или `kapat` и датчик усилия
  (`[load_cell]` или `[load_cell_probe]`) в сопле. Их установщики также кладут веб-интерфейс на
  сайт nginx (`/autopa/`, `/kapat/`).
- Tessera с plugin API **1.0** или новее и `@core/calibrations` 3.0.0 или новее.

Код провайдеров в плагин не копируется (оба под AGPL-3.0): он только встраивает их интерфейс и
следит за их G-code командами.

## Какой провайдер показан

1. Установленные провайдеры определяются по команде в G-code справке Klipper: `AUTOPA_SWEEP` — это
   autopa, `KAPAT_SWEEP` — KAPAT. Объекты `autopa` / `kapat` в `objects/list` — вторая подсказка.
   Проверка идёт при открытии вкладки, после перезапуска Klipper и по кнопке **Проверить снова**.
2. Один провайдер показывается сразу. Если их два, появляется переключатель; последний выбор
   запоминается на принтер (`api.settingsFor(printerId)`). По умолчанию первым идёт autopa.
3. Ни одного: инструкции по обоим.

## Где веб-интерфейс

Iframe — это прямое подключение браузера к сайту провайдера, а не через прокси Moonraker. Оба
установщика добавляют `/autopa/` или `/kapat/` в **первый найденный сайт nginx** — это может быть
сайт Tessera (порт 8000 по умолчанию) или сайт Mainsail/Fluidd (порт 80). Поэтому плагин пробует по
порядку:

1. адрес, который ввели вы (кнопка **Адрес**; хранится на принтер и провайдера, используется как есть);
2. `<origin этой страницы>/autopa/`;
3. `<хост принтера>/autopa/` на порту по умолчанию для схемы страницы.

Кандидат считается найденным, если:

- он на том же origin, что и Tessera, и отдаёт страницу, отличную от корня сайта (nginx самой
  Tessera может отвечать на неизвестные пути своим `index.html`);
- он на другом origin и вообще отвечает. Браузер скрывает статус такого ответа, поэтому 404 там не
  отличить от рабочего интерфейса: если рамка пустая, введите правильный адрес.

Если не отвечает ничего, вкладка перечисляет, что пробовала.

**HTTPS.** Страница Tessera, открытая по HTTPS, не может встроить HTTP-страницу. Вкладка сообщает об
этом и предлагает **Открыть в новой вкладке**. Та же кнопка выручает, если ваш nginx запрещает
встраивание (`X-Frame-Options`, `Content-Security-Policy`); установщики провайдеров эти заголовки
не ставят.

**Живой график KAPAT.** График KAPAT подключается напрямую к `:7125/klippysocket`, мимо nginx.
Tessera проксирует только `/websocket`, поэтому за обратным прокси, который не пробрасывает порт 7125,
интерфейс KAPAT работает, а его график пуст. Здесь это не исправляется.

## Гард

Гард отклоняет `AUTOPA_SWEEP`, `AUTOPA_DECAY` и `KAPAT_SWEEP`, набранные в консоли Tessera (или
отправленные макросами других плагинов), пока идёт печать или пауза. Исходные оси и температуру он
не проверяет: оба модуля греют и двигают по своим настройкам. Подтверждения не спрашивает. Если
состояние принтера прочитать нельзя, команда пропускается: Klipper всё равно отклонит то, что не
может выполнить.

Прогоны, запущенные **внутри веб-интерфейса провайдера** (наш iframe), идут прямо в Moonraker, и
никакой гард Tessera их не видит. Вкладка об этом предупреждает.

## Разработка

Исходники лежат в репозитории реестра, `Tessera-Ext/plugins/pa-autotune/`. Склонируйте Tessera рядом
(`TESSERA_ROOT` переопределяет раскладку для сборки и `pack`):

```
…/Tessera/                          хост (dev-сервер, типы plugin-sdk, registry-pack.cjs)
…/Tessera-Ext/plugins/pa-autotune/  этот плагин
```

```bash
npm install
npm run dev        # vite build --watch → dist/ и Tessera/extensions/pa-autotune/
npm test           # детект, адреса, выбор, гард + контрактный тест хоста
npm run typecheck
```

В Tessera один раз выполните `node tools/extensions-sync.cjs`, чтобы каталог показал плагин. Затем
Settings → Plugins → Install «PA Autotune» и F5 после правок кода.

Третий инструмент — это ещё одна строка в `src/providers.ts` и его строки в `src/i18n/`.

## Публикация

Поднимите `version` в `manifest.json`, выполните `npm run pack` (собирает и пишет
`registry/pa-autotune-<version>.tar.gz` и его запись в `registry.json`), запустите
`node scripts/verify-registry.mjs` в корне репозитория, закоммитьте исходники, архив и
`registry.json` вместе.

## Как подключается к Tessera

| Файл | Точка интеграции |
|---|---|
| `manifest.json` | `extensions[]`: точка `@core/calibrations#tabs`, kind `tab`, без `available` (показывается всегда); `pluginApi: "1.0"` |
| `src/ui/autotune-tab.ts` | само дополнение: состояния «нет / один / несколько провайдеров», iframe, поле адреса |
| `src/providers.ts` | провайдеры как данные: команда, путь, репозиторий, шаги установки |
| `src/detect.ts` | `printer.gcode.help` + `printer.objects.list` → установленные провайдеры |
| `src/url.ts` | кандидаты адреса, проверка доступности, проверка mixed content |
| `src/selection.ts` | какой провайдер показать первым; ключи настроек |
| `src/guard.ts` | собственный гард; собственные запросы собственные гарды пропускают |
